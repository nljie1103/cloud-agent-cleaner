# 威胁模型与能力边界

## 本项目要解决的问题

云服务器镜像经常包含远程运维、监控、安全、部署和 Guest Agent。管理员可能不知道它们是否存在、由谁启动、连接哪些服务、卸载后有什么影响。

本项目提供：

1. 可重复的本机检测；
2. 明确的 Agent 名称、用途和影响说明；
3. 精确选择、预演、禁用和卸载；
4. 核心组件保护、日志和卸载后复查。

## 本项目不假设什么

检测到 Agent 不等于发现恶意软件，也不能单凭“会联网”判定云厂商正在非法监控。多数 Agent 的合法用途由厂商公开文档说明，包括远程命令、指标上报、安全检测、扩展处理和网络配置。

## 能降低的风险

成功禁用或卸载后，可以降低特定 Guest OS 进程带来的：

- 本机常驻进程和攻击面；
- 通过该 Agent 执行控制面远程命令的能力；
- 由该 Agent 主动上传的日志、指标或安全遥测；
- 不需要的自动部署、更新和安全扫描功能；
- 资源消耗和软件供应链范围。

## 无法消除的信任关系

购买公有云虚拟机仍然意味着信任基础设施提供商。删除 Guest Agent 不能阻止或改变：

- 宿主机、Hypervisor 和虚拟硬件控制；
- 实例启动、停止、重置和销毁；
- 虚拟网络、安全组、路由和公网入口；
- 云盘、快照、备份和镜像控制面；
- 宿主机侧的 CPU、网络、磁盘等基础指标；
- 依法合规的数据保存或访问流程；
- 控制面策略、VM 扩展或镜像初始化重新部署软件。

因此，本项目不是“让云厂商完全无法看到服务器”的工具，也不应作此宣传。

## 更完整的加固建议

- 使用最小化、自建或可复现镜像；
- 对磁盘和应用数据实施用户自持密钥加密；
- 使用出站防火墙、DNS 日志和网络流量审计；
- 关闭不需要的云控制面功能与自动安装策略；
- 使用最小权限 IAM、硬件密钥和独立备份；
- 对高敏感工作负载评估 Confidential VM、专用宿主机或自建硬件；
- 保留串口/VNC/带外恢复路径和定期快照；
- 删除厂商安全 Agent 后，用自主选择的 EDR、审计和补丁机制补位。

## 非目标

本项目不会：

- 绕过 Agent 自保护；
- 清除云厂商账单、资产记录或控制面日志；
- 删除驱动、`cloud-init`、`qemu-guest-agent` 或未知软件；
- 尝试规避服务条款、调查或合法合规要求；
- 承诺卸载后服务器“绝对私密”或“绝对安全”。
